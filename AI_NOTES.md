## Where the generated code was wrong

1. **Deadlock in parallel transfers.**
   - **What was wrong:** the first version locked accounts with `SELECT … FOR UPDATE`
     in id order and looked correct. But the request first inserts an
     `idempotency_keys` row with a foreign key to `accounts`, and that takes `FOR KEY
     SHARE` on the account row. Two parallel transfers from the same account each held
     KEY SHARE and waited for the other's FOR UPDATE.
   - **How it was noticed:** `test_parallel_transfers_never_overdraw` failed with
     `deadlock detected`.
   - **Fix:** lock with `FOR NO KEY UPDATE` (the lock an `UPDATE` of non-key columns
     takes anyway).

2. **Idempotency table schema that couldn't work.**
   - **What was wrong:** the model declared `response_status` / `response_body` as
     `NOT NULL`. The key row is inserted *before* the operation runs, so the response
     isn't known yet.
   - **How it was noticed:** while writing the claim → execute → store flow, before the
     first test run.
   - **Fix:** made both columns nullable and documented the invariant: committed rows
     always have them filled, because they are written in the same transaction.

3. **Autogenerated migration missing server defaults.**
   - **What was wrong:** Alembic `--autogenerate` produced tables where `balance_usd`,
     `credits`, `credits_delta` and `status` had only Python-side defaults. Any insert
     not done through the ORM would fail.
   - **How it was noticed:** by reading the generated migration instead of trusting it.
   - **Fix:** added `server_default`s, plus `CHECK` constraints (amount > 0, no
     self-transfer, credits > 0) as defence in depth.

4. **Rate limiter broke every POST.**
   - **What was wrong:** the advisory-lock key was built with
     `hashtextextended(CAST(:account_id AS TEXT))`. SQLAlchemy bound the Python `UUID`
     as a text parameter, and asyncpg rejected it with `DataError: expected str, got
     UUID`.
   - **How it was noticed:** 82 tests failed at once.
   - **Fix:** pass `str(account_id)`.

5. **Smoke test false failure.**
   - **What was wrong:** the script read `Idempotent-Replayed` from
     `dict(response.headers)`, a case-sensitive dict. Uvicorn sends lowercase header
     names.
   - **How it was noticed:** the smoke test reported a missing header even though the
     replay itself worked.
   - **Fix:** use the case-insensitive `HTTPMessage`.

6. **Crash paths the AI-written code and tests both missed.**
   - **What was wrong:** the code passed all its own tests, but an independent review
     agent found inputs that ended in a 500 instead of a clean 4xx:
     - a correctly signed webhook with an extra `NaN` or `"\u0000"` field (stored into
       JSONB, which rejects both);
     - a 400-digit `X-Timestamp` (`OverflowError`, and no signature needed);
     - a history cursor above BIGINT;
     - a non-ASCII bearer token in provider-mock (`hmac.compare_digest` on `str`).
   - **Same review, other issues:** reconciliation always re-read the same 500 oldest
     deposits, so it could starve. The Postgres healthcheck used the unix socket, which
     the image's init server answers before TCP is up.
   - **Fix:** each was fixed with a regression test; the healthcheck now uses
     `-h 127.0.0.1`.
